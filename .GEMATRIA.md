# .GEMATRIA.md — Steve's Gematria Wiki Schema

## 🎯 Overview

This schema defines how the LLM agent maintains and evolves the Steve's Gematria knowledge base. It ensures consistent, high-quality wiki maintenance across all analysis activities.

**Current State:**
- Raw sources: `database/gematria_database.json` (analysis results)
- Wiki layer: `obsidian_exports/` (markdown pages for symbols, domains, forces)
- Schema: This file (read-only configuration for the agent)

---

## 📐 Core Principles

1. **Persistence over Retrieval:** Every analysis updates existing pages rather than just querying fresh data
2. **Cross-reference Priority:** All new analyses must link to relevant core symbols, domains, and elemental forces
3. **Elemental Force Tracking:** Each symbol/domain must be classified under active elemental forces (fire, volcano, frequency, resonance)
4. **Temporal Awareness:** Maintain chronological timeline in `ANALYSIS_TIMELINE.md`
5. **Relationship Extraction:** Every new analysis must identify connections between:
   - Symbols ↔ Domains
   - Symbols ↔ Elemental Forces
   - Domains ↔ Elemental Forces
   - Image patterns ↔ Textual concepts

### Required Pages (Maintain These):

## 🔍 Ingestion Workflow

When processing a new analysis result from `gematria_database.json`:

### 1. **Read Schema & Existing Wiki**
- Load `.GEMATRIA.md` for current conventions
- Read all wiki pages in `obsidian_exports/`
- Check `RELATIONSHIP_MATRIX.md` for existing connections
- Review `ANALYSIS_TIMELINE.md` for recent activity

### 2. **Extract Core Entities**
From new analysis, identify:
- Which core symbols are mentioned?
- Which domains are active?
- Which elemental forces appear?
- What patterns emerge (transformations, reductions)?

### 3. **Update/Expand Wiki Pages**
For each entity found:
- Update relevant symbol page in `CORE_SYMBOLS_SUMMARY.md`
- Add connections to `RELATIONSHIP_MATRIX.md`
- Log in `ANALYSIS_TIMELINE.md`
- Update cross-reference index if new top-20 connections formed

### 4. **Extract Relationships**
For every pair of entities (symbols, domains, forces):
```python
# Relationship extraction pattern:
relationship = {
    "from": entity1,
    "to": entity2,
    "strength": calculated_or_expert_score,  # 0.0-1.0
    "context": "brief context or quote",
    "source": "file_ref_or_url"
}
```

**Minimum required:** Every new analysis must extract at least 3 relationships.

### 5. **Maintain Relevance Scores**
Update `RELATIONSHIP_MATRIX.md` with:
- New relationships from current analysis
- Incrementally increase scores for frequently referenced connections
- Flag stale relationships (>30 days without mention)

## 📊 Relationship Extraction Rules

### Priority Connection Types:

1. **Symbol ↔ Symbol Transformations** (Highest priority)
   - Example: `666 → 9` via reduction
   - Example: `124 ↔ 963` cycle turning variants
   - Update score based on frequency of appearance together

2. **Domain Activation Convergence**
   - When political + religious domains both reference symbol X
   - Example: Political events mentioning core symbols → increase political relevance

3. **Elemental Force Resonance**
   - Fire/volcano appearing with specific numbers
   - Frequency/resonance in image/text patterns
   - Track elemental "activations" and their contexts

4. **Cross-Domain Symbol References**
   - Example: Economic domain referencing military symbol 124
   - Example: Religious concepts linking to elemental fire force

## 🧹 Lint Operations (Run Periodically)

### Health Check Tasks:

1. **Contradiction Detection:**
   ```
   - Scan CORE_SYMBOLS_SUMMARY.md for conflicting definitions
   - Flag: "Symbol 124 defined as X in page A but Y in page B"
   ```

2. **Stale Claim Review:**
   ```
   - Cross-reference ANALYSIS_TIMELINE.md with current database
   - Flag claims from >60 days ago without updates
   - Example: "Symbol 963 mentioned in old report, check if new data exists"
   ```

3. **Orphan Page Detection:**
   ```
   - Check each wiki page has inbound links from index.md
   - Orphaned pages = pages not referenced in any other markdown
   - Either add references or archive as deprecated
   ```

4. **Missing Concept Pages:**
   ```
   - Search ANALYSIS_TIMELINE.md for concepts without entity pages
   - Example: "Military coup" mentioned frequently → create MILITARY_COUP.md page
   ```

5. **Cross-Reference Validation:**
   ```
   - Verify every connection in RELATIONSHIP_MATRIX.md points to existing pages
   - Flag broken links or missing referenced entities
   ```

## 🎯 Quality Standards

### Every Analysis Must Include:
- ✅ At least 2 new relationships extracted
- ✅ Cross-references to core symbols (124, 963, etc.)
- ✅ Domain classification (political, religious, economic, military, elemental)
- ✅ Elemental force tagging (fire, volcano, frequency, resonance)
- ✅ Source citation (file reference or URL)

### Every Update Must:
- ✅ Preserve existing content (never delete without reason)
- ✅ Add chronological entry to ANALYSIS_TIMELINE.md
- ✅ Update RELATIONSHIP_MATRIX.md with new connections
- ✅ Flag contradictions if found
